# Layers clients immobiliers

## Composition

Une build sert un client sélectionné par `GD_TARGET`, Showcase par défaut.
La racine choisit `sites/<client>/app/` comme `srcDir` et étend sa configuration.
Une cible invalide ou inconnue interrompt Nuxt. Les sites ne sont pas placés dans
`layers/`, dont Nuxt active automatiquement les sous-dossiers.

Showcase seul étend `base/real-estate/`. Cette layer déclare `srcDir: '.'` et le
scan explicite de `components/` : `screen/` conserve les noms `Screen*` et
`LazyScreen*`. Une surcharge de même nom dans le site reste prioritaire.
Les screens dépendent encore des composants, composables et stores Showcase ;
leur autonomie est reportée. Client 2 ne charge pas ce catalogue.

| Périmètre                                           | Responsabilité                                                                 |
| --------------------------------------------------- | ------------------------------------------------------------------------------ |
| `sites/showcase-immobilier/app/`                    | application historique, styles, identité, menus, parcours publics et dashboard |
| `base/real-estate/components/screen/`               | les 16 screens extraits, sans leurs dépendances                                |
| `sites/client2-immobilier/`                         | page SSR française minimale, sans données ni dashboard                         |
| `server/`                                           | BFF commun, explicitement activé par Showcase seulement                        |
| `services/`, `shared/`, `schemas/`                  | logique et contrats partagés                                                   |
| `sites/<client>/content/`, `public/`, `themes.yaml` | données, médias et thème du client qui les utilise                             |
| `sites/<client>/site.ts`                            | identité compilée de la cible                                                  |

Les conventions frontend restent dans
[leur README unique](../../webapp/sites/showcase-immobilier/app/README.md).
Les alias `~`, `@`, `@utils` et `@site-assets` ciblent l’app active. La configuration
TypeScript préparée (`.nuxt/tsconfig.site.json`) conserve la politique d’alias historique en calculant les
chemins clients ; les fichiers `.nuxt/` sont générés et ne se modifient pas à la main.

## Construire et déployer

Depuis `webapp/`, choisir explicitement la cible :

```bash
GD_TARGET=showcase-immobilier bun run type-check
GD_TARGET=showcase-immobilier bun run build
GD_TARGET=client2-immobilier bun run type-check
GD_TARGET=client2-immobilier bun run build
node .output/server/index.mjs
```

Construire successivement : `.nuxt` et `.output` sont propres au checkout courant.
Chaque image Docker possède ses sorties. La cible serveur est figée par `#site` ;
changer `GD_TARGET` au démarrage ne change pas l’application servie.

Showcase conserve ses langues `/fr`, `/en`, `/es`, son dashboard, ses modules,
initialisations et routes BFF. Son hook embarque contenu et thème dans
`.output/site/showcase-immobilier/`. Client 2 possède son serveur vide et construit
sans contenu ni thème Showcase. La préparation des types génère les contrats
communs depuis les sources YAML pour chaque cible, sans bootstrap métier. Déployer le `.output` complet.

`CONTENT_PATH` surcharge explicitement la projection lue et écrite par Showcase ;
`CONTENT_SYNC_MEDIA_DIR` surcharge les médias synchronisés. Les demandes de contact
restent dans `.data/<client>/`. Chaque instance avec données conserve son projet
Symfony, son environnement, ses secrets et volumes propres. Les `.env` sont préservés.

En local, `make dev-webapp-ssr BUILD=1` construit et sert les deux cibles derrière
Nginx. Après une première construction, omettre `BUILD=1` pour réutiliser les images.
Les noms HTTP et ports publics sont les suivants :

| Pile | Showcase | Client 2 | Port |
| --- | --- | --- | --- |
| Principal | showcase-immobilier.preprod.localhost | client2.preprod.localhost | 8080 |
| Web | showcase-immobilier.wt-web.localhost | client2.wt-web.localhost | 19401 |
| BFF | showcase-immobilier.wt-bff.localhost | client2.wt-bff.localhost | 19402 |
| Domaine | showcase-immobilier.wt-domaine.localhost | client2.wt-domaine.localhost | 19403 |
| DevOps | showcase-immobilier.wt-devops.localhost | client2.wt-devops.localhost | 19404 |

Ouvrir `/fr`, `/en` ou `/es` pour Showcase, `/` pour Client 2, avec le port indiqué.
`preprod` désigne ici le principal local ; aucun environnement distant n’est modifié.
Les anciens alias et tout hôte hors des deux noms de la pile sont refusés en HTTP 421.

Nginx route vers deux serveurs SSR distincts ; Nuxt ne sélectionne pas son client
par Host. Client 2 ne reçoit ni env_file, ni secrets, ni volumes de données Showcase.
La [configuration Nginx](../../infra/nginx/README.md) décrit le rendu du gabarit.
`make dev-check-ssr` découvre le port et la couche du Nginx actif, contrôle les deux
identités, les routes et le refus des noms non autorisés. Sans pile active, il échoue.
Démarrage et préparation : [guide local](../1.getting-started/setup-local.md).
Les [worktrees](../../worktree/README.md) conservent leurs ports et données isolés.
Le développement direct reste sur localhost:3000 et les ports 19301–19304 des couches.

## Ajouter un client

1. Créer `sites/<identifiant>/site.ts`, une config et une app propres ; l’identité
   doit correspondre au dossier. Client 2 fournit l’exemple minimal.
2. Déclarer explicitement le serveur, les modules et les éventuelles layers métier.
   Ne pas hériter du bootstrap Showcase pour une cible vide.
3. Fournir uniquement les contenus, thèmes et médias réellement nécessaires à la
   cible. Ne pas copier les secrets ou données d’un autre client.
4. Vérifier types, tests, build, SSR et navigateur pour cette cible, puis affecter
   son environnement et ses volumes. Git seul n’isole pas une API externe.

Les données non versionnées ne se déduisent pas d’un checkout neuf. Le setup de
Showcase conserve ses protections contre l’écrasement de données réelles ; il ne
constitue pas une commande d’initialisation métier pour Client 2.
